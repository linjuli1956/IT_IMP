## 一、文档目的与范围

### 1.1 目的

现有服务器管理页面存在两类问题：

- **P0 数据一致性缺陷**：编辑/删除后只刷新分页列表（`serverList`），未刷新"全部"卡片依赖的 `serverTree`，导致物理机页显示新数据而"全部"页显示旧数据。
- **交互架构缺失**：三个 Tab 各自维护不同数据刷新规则；卡片信息层级未规范；缺少详情抽屉与悬停预览的统一标准。

本规范定义统一的页面结构、数据刷新机制、卡片信息层级、悬停预览规则和视觉语义，作为阶段 1~5 的实施基线。

### 1.2 范围

| 模块分类 | 模块 | 交互模式 |
|----------|------|----------|
| 资产类 | 服务器、网络设备、固话、电脑、电子称 | 卡片总览 + 筛选 + 分页 + 详情抽屉 + 悬停预览 |
| 资产类 | 域名、小程序、支付配置 | 卡片总览 + 筛选 + 分页 + 详情抽屉 + 悬停预览 |
| 资金/预算类 | 预算、计提、发票 | 表格为主，悬停预览复用，不强行卡片化 |

### 1.3 三角色权限矩阵

| 角色 | 查看 | 新增 | 编辑 | 删除 | 密码管理 |
|------|------|------|------|------|----------|
| 管理员 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 操作员 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 查看者 | ✓ | ✗ | ✗ | ✗ | ✗ |

查看者：卡片不显示"编辑/更多/密码"操作按钮；悬停预览不含敏感字段；抽屉详情只读。

## 二、P0 数据同步修复方案

### 2.1 缺陷定位

**文件**：`web/app/pages/it/servers.vue`

```
// 当前（有缺陷）：handleSave / handleDelete / handleBatchDelete 成功后只刷新 3 个数据源
await Promise.all([fetchServers({ ...buildQuery() }), fetchServerStats(), fetchPhysicalHosts()])
// ↑ 缺少 fetchServerTree() — "全部"卡片依赖 serverTree，显示旧数据
```

**影响范围**：
- 编辑物理机 `manageUrl` → "全部"Tab 宿主卡仍显示旧地址
- 新增虚拟机 → "全部"Tab 宿主卡 `vmCount` 不更新
- 删除服务器 → "全部"Tab 仍显示已删除的记录

### 2.2 修复方案：useServerWorkspace + refreshWorkspace

**架构分层**：

- `useServerData`（数据层）：只保留 API 请求与数据状态（`serverList`、`serverTree`、`treeError` 等），不拥有页面筛选条件。
- `useServerWorkspace`（工作区层）：管理 `query`（唯一筛选/Tab/页码状态）、`refreshWorkspace()`（唯一写操作后刷新入口）。

```typescript
// composables/useServerWorkspace.ts — 新建

export function useServerWorkspace() {
  const { /* 从 useServerData 透传 */ } = useServerData()

  // 唯一筛选/Tab/页码状态
  const query = reactive<ServerWorkspaceQuery>({
    keyword: '', status: '', hypervisor: '',
    hostServerId: undefined, activeTab: 'all',
    page: 1, pageSize: 20,
  })

  function buildQuery(): ServerQueryParams { /* 从 query 派生标准化查询参数 */ }

  /** 统一刷新入口：所有写操作成功后只能调用此函数 */
  async function refreshWorkspace(): Promise<boolean> {
    workspaceRefreshError.value = false
    const q = buildQuery()
    const results = await Promise.allSettled([
      fetchServers(q), fetchServerTree(),
      fetchServerStats(), fetchPhysicalHosts(),
    ])
    // 明确处理 tree/list/stats/hosts 任一失败
    const treeFailed = results[1].status === 'rejected' || Boolean(treeError.value)
    const listFailed = Boolean(listError.value)
    const statsFailed = Boolean(statsError.value)
    const hostsFailed = Boolean(hostsError.value)
    if (treeFailed || listFailed || statsFailed || hostsFailed) {
      workspaceRefreshError.value = true
      ElMessage.error('数据同步失败，请重试')
      return false  // 不显示"已同步"假象
    }
    return true
  }

  return { query, buildQuery, refreshWorkspace, treeError, workspaceRefreshError, /* ... */ }
}
```

**`fetchServerTree` 修复**（`useServerData.ts`）：

```typescript
// 修复前（静默吞错）
catch (e) { console.error('获取服务器树失败', e) }

// 修复后（设置 treeError + re-throw）
const treeError = ref('')
async function fetchServerTree() {
  treeError.value = ''
  try { /* ... */ }
  catch (e) {
    treeError.value = e instanceof Error ? e.message : String(e)
    throw e  // 不再静默吞错，让 refreshWorkspace 能检测到失败
  }
  finally { /* ... */ }
}
```

同样为 `fetchServers` 增加 `listError`、`fetchPhysicalHosts` 增加 `hostsError`（设置但不 re-throw，避免破坏现有 fire-and-forget 调用）。

**调用点替换**（`servers.vue`，阶段 1 执行）：

| 当前代码位置 | 当前调用 | 替换为 |
|-------------|---------|--------|
| `handleSave()` 成功后 (line ~795) | `Promise.all([fetchServers, fetchServerStats, fetchPhysicalHosts])` | `await refreshWorkspace()` |
| `handleDelete()` 成功后 (line ~812) | 同上 | `await refreshWorkspace()` |
| `handleBatchDelete()` 成功后 (line ~823) | 同上 | `await refreshWorkspace()` |
| `onMounted` (line ~536) | `Promise.all([...])` 无错误处理 | 包裹 try-catch 或迁移至 `useServerWorkspace` |

### 2.3 Tab 数据流统一

"全部 / 物理机 / 虚拟机"是同一份服务器数据的三个视图，不是三套独立逻辑：

```
                        ┌─ fetchServerTree() → serverTree (全量，不分页)
refreshWorkspace() ─┼─ fetchServers()     → serverList (分页，按 Tab 筛选)
                        ├─ fetchServerStats()  → 统计数据
                        └─ fetchPhysicalHosts()→ 宿主下拉

视图派生（纯前端 computed）：
  全部 Tab   → treeData = buildServerTree(serverTree 筛选后)
  物理机 Tab → physicalServerList = serverList.filter(!isVirtual)
  虚拟机 Tab → virtualServerList = serverList.filter(isVirtual)

query 状态由 useServerWorkspace 管理（不散落在页面 ref 中）。
buildQuery() 是唯一将 query 转为 ServerQueryParams 的入口。
```

### 2.4 全部 Tab 筛选规则（明确）

| 规则 | 说明 |
|------|------|
| 先筛选后构建树 | 对扁平 `serverTree` 数据应用统一筛选，再 `buildServerTree` 构建树 |
| VM 命中关键词 → 宿主机保留 | 若 VM 命中关键词但宿主机未命中，宿主机仍保留并只显示命中的 VM |
| 平台筛选以宿主平台为准 | VM 的平台筛选条件检查其宿主机的 `hypervisor`，而非 VM 自身 |
| 状态筛选对子节点 | 状态筛选对宿主机和 VM 独立生效；宿主机因 VM 命中而保留时，仍需通过状态和平台筛选 |
| 筛选口径一致 | 页面列表和全部卡片筛选口径完全相同，不允许不同 |

### 2.5 manageUrl 业务归属

| 服务器身份 | manageUrl 字段 | 展示来源 |
|-----------|---------------|---------|
| 物理宿主机 / 云服务器 | 可保存（表单可编辑） | 自身 `manageUrl` |
| 虚拟机 | 不保存（表单不出现该字段，提交时强制 `null`） | 宿主机 `manageUrl`（API 返回 `hostManageUrl`） |

**保存成功后**：
- "全部"Tab 宿主卡 `manageUrl` 立即更新（`serverTree` 已刷新）
- 物理机 Tab 卡片 `manageUrl` 立即更新（`serverList` 已刷新）
- 该宿主下所有 VM 卡的"进入宿主机管理"入口立即更新（`hostManageUrl` 随 `serverTree` 刷新）
- 详情抽屉同步更新（从 `serverTree` 重新派生）

## 三、页面结构规范

### 3.1 整体布局

```
┌─────────────────────────────────────────────────────┐
│ PageHeader: 标题 + [新增服务器] [新增虚拟机]           │
├─────────────────────────────────────────────────────┤
│ el-alert: 使用说明（紧凑，≤2 行）                      │
├─────────────────────────────────────────────────────┤
│ 指标卡（4 个，紧凑型，一行排列）                        │
│  [总数] [物理机] [虚拟机] [即将到期]                     │
├─────────────────────────────────────────────────────┤
│ Tab: [全部] [物理机] [虚拟机]                          │
│ 筛选栏: [关键词] [状态] [平台] [宿主机]    [卡片|列表]   │
├──────────────────────────┬──────────────────────────┤
│                          │                          │
│   卡片网格（全宽主工作区）    │   ← 点击卡片弹出 AssetDetailDrawer   │
│   auto-fill 280px         │   （el-drawer 右侧弹出， 400px）        │
│   gap 16px                │   可 Esc 关闭、焦点陷阱            │
│                          │   深信息展示 + 操作按钮            │
│                          │                          │
├──────────────────────────┴──────────────────────────┤
│ 分页（物理机/虚拟机 Tab 后端分页；全部 Tab 前端分页）      │
└─────────────────────────────────────────────────────┘
```

### 3.2 布局规则

| 规则 | 说明 |
|------|------|
| 默认展示 | 三个 Tab 均为卡片模式 |
| 卡片/列表互斥 | `viewMode` 切换时只渲染当前模式，不同时渲染 |
| 不持久化展示偏好 | 重新进入页面默认卡片模式（`viewMode` 不写 localStorage） |
| 树形列表是辅助模式 | 用户主动切换才显示；默认不展示 |
| 筛选栏高级筛选 | 关键词、状态、平台、宿主机始终可见；无折叠 |
| 指标卡紧凑 | ≤4 个，一行排列，不占大面积 |

### 3.3 响应式断点

| 分辨率 | 布局调整 |
|--------|---------|
| ≥1440px | 卡片网格全宽；点击卡片弹出抽屉（400px） |
| 1366~1439px | 卡片网格全宽；抽屉弹出宽度 360px |
| ≤1365px | 卡片网格全宽；抽屉全屏覆盖 |

## 四、双列工作台设计

### 4.1 左侧：卡片网格

- `display: grid; grid-template-columns: repeat(auto-fill, minmax(280px, 1fr)); gap: var(--spacing-card);`
- 卡片点击主体区域 → 打开右侧详情抽屉
- 操作按钮（编辑、更多、进入管理）独立，`@click.stop` 阻止冒泡，不误触打开抽屉

### 4.2 右侧：AssetDetailDrawer（弹出抽屉，非常驻面板）

**组件**：`AssetDetailDrawer`（基于 `el-drawer`，右侧弹出，`direction="rtl"`）

> **明确**：本规范使用「抽屉」（Drawer），即 `el-drawer` 弹出层，支持 Esc 关闭、焦点陷阱、`destroy-on-close`。
> 不使用「常驻检查面板」（Inspector Pane）概念。文档、组件名、代码三者一致。

**触发**：点击卡片主体（非操作按钮区域）

**内容**（通过插槽传入）：
- `#header`：身份与状态 Tag
- 默认插槽：`el-descriptions` 基础信息 + 虚拟机列表/宿主信息
- `#footer`：操作按钮区（详情页、编辑、密码管理、进入管理）

**行为**：
- 可关闭（右上角 × 或 Esc 键）— 由 `el-drawer` 原生提供
- 不发新 API 请求 — 数据来自 `serverTree`（已全量加载）
- 物理机：展示其下全部虚拟机摘要列表
- 虚拟机：展示宿主信息卡片
- 查看者：隐藏编辑/密码管理按钮（`canEdit` 控制）

### 4.3 数据来源

| 抽屉内容 | 数据源 | 刷新时机 |
|---------|--------|---------|
| 基础信息 | `serverTree` 中对应记录 | `refreshServerWorkspace()` 后自动更新 |
| 虚拟机列表 | `serverTree` 中该宿主的 children | 同上 |
| 宿主信息 | `serverTree` 中该 VM 的 `hostServerName` 等 | 同上 |
| 管理地址 | `serverTree` 中 `manageUrl` / `hostManageUrl` | 同上 |

## 五、卡片信息层级

### 5.1 宿主机卡（ServerHostCard）

**默认展示**：

| 区域 | 字段 |
|------|------|
| 头部 | 名称（链接）、平台 Tag、状态 Tag |
| 网络信息 | 内网 IP、外网 IP（可空 → —） |
| 硬件规格 | CPU 型号·核数、内存、系统盘、数据盘 |
| VM 缩略 | 最多 3 台 VM 名称（链接），超出显示 `+N 台…` |
| 底部 | `N 台虚拟机 · 类型` + `进入管理`（仅 manageUrl 存在时） |

**操作按钮**（`canEdit` 时显示）：
- 编辑（`@click.stop`）
- 更多 → 删除（`@click.stop`）

### 5.2 虚拟机卡（ServerVmCard）

**默认展示**：

| 区域 | 字段 |
|------|------|
| 头部 | 名称（链接）、平台 Tag、`虚拟机` Tag、状态 Tag |
| 网络信息 | 内网 IP、外网 IP（可空 → —） |
| 分配资源 | 分配 CPU、分配内存、分配磁盘、操作系统 |
| 归属 | 宿主机名称（链接） |
| 底部 | 宿主机名称 或 `未分配` + `进入宿主机管理`（仅宿主有 manageUrl 时） |

**操作按钮**（`canEdit` 时显示）：
- 编辑（`@click.stop`）
- 更多 → 删除（`@click.stop`）

### 5.3 卡片禁止行为

- 不请求 API
- 不保留旧 props（数据由父级传入，`refreshServerWorkspace` 后自动更新）
- 不硬编码颜色（使用 `serverToneClass` + tokens 变量）
- 不展示密码、账号等敏感字段

## 六、悬停预览规范

### 6.1 组件复用

复用现有 `RecordPreviewTooltip`（`components/common/RecordPreviewTooltip.vue`），配合强类型预览构建函数 `server-preview.ts`。

- `RecordPreviewTooltip` 已支持 `trigger: ['hover', 'focus']`（hover + 键盘 focus 均可触发）。
- 通过 `#reference` 插槽传入触发元素（带 `tabindex="0"` 和 `aria-label`）。
- 敏感行过滤：`filterSensitiveRows` 已内置，密码/账号字段永不进入 DOM。
- `maxRows` 限行：超出部分提示「其余 N 项见详情页」。

### 6.2 预览构建函数

**文件**：`app/utils/server-preview.ts`（新建）

**宿主机悬停预览**（`buildHostPreviewRows`）：

| 行 | 字段 |
|----|------|
| 1 | 厂商 / 型号 / 序列号 |
| 2 | 系统 / 用途 |
| 3 | 内网IP / 外网IP |
| 4 | CPU / 内存 / 磁盘 |
| 5 | 虚拟机数量 |
| 6~10 | 最多 5 台 VM：名称、IP、用途、状态 |
| 末行 | 其余 N 台见详情（超出 5 台时） |

**虚拟机悬停预览**（`buildVmPreviewRows`）：

| 行 | 字段 |
|----|------|
| 1 | 宿主机 / 平台 |
| 2 | 系统 / 用途 |
| 3 | 内网IP / 外网IP |
| 4 | 分配 CPU / 内存 / 磁盘 |
| 5 | 宿主机管理入口状态 |
| 6 | 状态 |

### 6.3 规则

| 规则 | 说明 |
|------|------|
| 不发新 API 请求 | 内容来自当前列表 DTO（`serverTree` 记录） |
| hover / focus 均可触发 | `trigger: ['hover', 'focus']` |
| 不含密码/账号 | 敏感字段不进入 tooltip DOM |
| 操作按钮区域不触发 | `@click.stop` + `@mouseenter.stop` |
| 键盘 Tab 可访问 | 卡片名称链接带 `tabindex="0"` |
| 最多 2 行截断 | 值超长用 `line-clamp: 2` 截断 |

|------|-------------|------|

### 7.3 颜色 Token 规则

- 卡片背景使用 `server-tone-*` class（已定义）。
- 禁止按服务器 ID 随机配色。

### 7.4 视觉一致性

PVE 与 ESXi 在以下位置颜色语义必须一致：
- 全部 Tab 卡片
- 物理机 Tab 卡片
- 虚拟机 Tab 卡片
- 树形列表行
- 详情抽屉
- 悬停预览
