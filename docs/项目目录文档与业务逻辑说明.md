> 版本：V0.01
> 更新日期：2026-07-27

---

## 一、项目概述

泰兴超市信息部综合管理平台是面向超市信息部的综合费用管理IT系统，覆盖通讯费用报销全流程：发票管理→明细表→计提生成→预算对比→支付配置，同时管理合同、IT资产（服务器/域名/小程序）和系统用户权限。

### 三层架构

| 层 | 技术栈 | 说明 |
|----|--------|------|
| EXE 配置器 | Go + Wails 2 | 桌面应用，配置远程 MySQL 连接、JWT 密钥，启动/停止 Web 服务 |
| Web 应用 | Nuxt 4 + Vue 3 + Element Plus | 前后端一体，提供 18 个页面 + 60 个 API |
| 数据层 | Prisma 7 + MySQL 8.0 | 远程 MySQL，15 张数据表，utf8mb4 字符集 |

### 1. 首页（/）

**页面文件**：`app/pages/index.vue`
**数据源**：useBudgetData / useInvoiceData / useAccrualData / useContractData / useServerData / useDomainData / useMiniappData

#### 业务逻辑

首页是数据看板，展示当前财年的业务概览和 IT 资产状态，所有数据从各 composable API 实时拉取。

**业务指标卡片（4 个）**：
- 当月预算：取当前财年当前月的预算明细汇总
- 发票批次：批次总数
- 计提金额：所有计提记录总金额
- 合同即将到期：状态为 expiring 的合同数

**IT 资产指标卡片（4 个）**：
- 服务器总数 / 域名总数 / 小程序总数 / 即将到期服务器数（≤90 天）

**ECharts 图表（4 个）**：
1. 月度预算趋势（折线图）：当前财年 12 个月，按运营商（电信/移动/联通）分线，考虑费用范围（feeRange）的月度生效
2. 各门店预算占比（饼图）：当前财年各门店年度预算，占比 <5% 合并为"其他门店"
3. 费用类型分布（柱状图）：当前财年按费用类型（宽带/固话手机/物联网/监控/云服务）汇总月度费用
4. 运营商预算排名（条形图）：当前财年按运营商汇总年度费用

**IT 资产概览**：
- 服务器类型分布：按 serverType 分组计数
- 即将到期服务器（≤90 天）：表格展示，剩余天数 ≤30 红色 / >30 黄色

**合同到期提醒**：
- 筛选状态为 expiring 或 expired 的合同，按剩余天数升序排列

### 2. 费用报销

#### 2.1 上传发票（/invoices/upload）

**页面文件**：`app/pages/invoices/upload.vue`
**API**：`POST /api/invoices/upload` + `POST /api/invoices/confirm`

##### 业务逻辑

上传运营商发票 PDF，系统自动 OCR 识别发票字段，人工确认后入库。

**操作流程**：
1. 选择运营商（电信/移动/联通）和费用月份
2. 选择关联门店（多选，默认全选）
3. 拖拽或点击上传 PDF 文件（支持 ZIP 压缩包，自动解压）
4. 系统自动调用 OCR 识别：
   - pdf-parser.ts 使用 pdfjs-dist v4 提取 PDF 文本
   - invoice-extractor.ts 通过 4 级金额策略识别价税合计：
     - 级别 1：(小写)金额关键字 + ¥ 符号
     - 级别 2：价税合计关键字 + 数字
     - 级别 3：纯数字匹配（最大值策略）
     - 级别 4：0 兜底
   - 同时识别发票号码、开票日期、销售方名称
   - 支持两栏布局（销售方/购买方）拆分
5. OCR 结果可编辑确认：金额、发票号、日期、销售方均可修改
6. OCR 失败时支持手动录入
7. 确认后发票状态变为 ocr-confirmed，创建发票批次（如不存在）

**文件存储**：PDF 存储到 `data/uploads/invoices/{batchNo}/` 目录

**权限**：上传需操作员以上角色

---

#### 2.2 批次列表（/invoices/batches）

**页面文件**：`app/pages/invoices/batches/index.vue`
**API**：`GET /api/invoices/batches` + `DELETE /api/invoices/batches/[id]`

##### 业务逻辑

管理发票批次，每个批次按运营商+费用月份维度组织。

**批次编号规则**：`年月+运营商缩写+序号`，如 `202606DX01`（2026年6月电信第1批）

**列表展示**：批次编号、运营商、费用月份、关联门店、发票数量、发票总额、状态、创建时间

**批次状态流转**：
- pending（待处理）→ accrued（已计提）→ printed（已打印）

**操作**：
- 查看批次详情：展示批次下所有发票列表
- 删除批次：级联删除批次下所有发票 + 删除物理 PDF 文件
- 生成计提表：跳转到计提生成页（批次 ID 传入）

#### 2.3 发票列表（/invoices/list）

**页面文件**：`app/pages/invoices/list.vue`
**API**：`GET /api/invoices`

##### 业务逻辑

所有发票的统一列表视图，支持按运营商、费用月份、状态筛选。

**展示字段**：发票文件名、运营商、费用月份、金额、发票号码、开票日期、销售方、状态、所属批次

**发票状态**：
- uploaded → ocr-pending → ocr-confirmed（正常流程）
- ocr-failed（OCR 失败，需手动录入）

**操作**：查看 PDF、删除发票（同步删除物理文件）

#### 2.4 明细表管理（/details）

**页面文件**：`app/pages/details/index.vue` + `app/pages/details/[id].vue`
**API**：`GET /api/details` + `POST /api/details` + `GET /api/details/[id]` + `DELETE /api/details/[id]`

##### 业务逻辑

上传运营商提供的电信费用明细 Excel（XLS），解析多 Sheet 页数据，用于计提生成时按号码行匹配。

**上传流程**：
1. 选择运营商和费用月份
2. 上传 XLS 文件
3. 后端使用 xlsx 库解析：

4. 文件存储到 `data/uploads/details/`

**详情页展示**：
- 按 Sheet 页分 Tab 展示
- 每个 Sheet 展示号码费用表格 + 合计行
- 支持关联批次查找（同运营商+同费用月）

**计提生成中的作用**：
- 电信模式：按号码行匹配明细表，有号码的费用按门店归属，无号码的费用跨门店倒推

**页面文件**：`app/pages/config/fee-schemes.vue`
**API**：`GET/POST/PUT/DELETE /api/fee-schemes`

##### 业务逻辑

通用费用分摊规则引擎，支持跨门店费用分摊，是计提模板的升级版。

**方案字段**：

**费用项 FeeItem 结构**：
- feeType：费用类型
- name：费用名称

| quantity | 按数量 | 按各门店设定的数量占比分摊 |
| manual | 手动 | 用户直接输入每个门店的金额 |

**联动规则**：amountSource=manual 时强制 allocationMode=manual

**报销说明生成**：通过共享函数 `reimbursement.ts` 的 `generateReimbursementText` 生成，支持 allocation 模式按费用类型分行组织

## 五、核心业务流程

### 5.1 费用报销全流程

```
1. 上传发票（OCR 识别 → 人工确认）
   ↓
2. 创建发票批次（运营商 + 费用月）
   ↓
3. 上传明细表（电信专用，XLS 解析）
   ↓
4. 生成计提表
   ├── detail 模式：电信 → 按明细表号码行匹配 + 跨门店倒推
   ├── invoice 模式：移动/联通 → 按发票金额均摊
   └── allocation 模式：费用分摊方案 → 四种分摊方式
   ↓
5. 计提表详情（编辑手动费用项 + 报销说明 + A5 打印）
   ↓
6. 预算对比（预算执行率分析）
```

### 5.2 计提生成核心算法

**电信（detail 模式）**：
1. 匹配明细表（运营商 + 费用月，三级匹配：精确 → 包含 → 全 Sheet 汇总）
2. 号码行匹配：按号码归一化（去横杠）匹配门店
3. 两遍计算：
   - 第一遍：汇总所有号码费用（allPhoneTotal）
   - 第二遍：非号码费用 = 发票总额 - allPhoneTotal，跨门店倒推
4. 发票金额不均摊（明细表模式显示完整总额）

**移动/联通（invoice 模式）**：
1. 按发票金额在各门店间均摊
2. 多门店时计算分摊差额

**分摊方案（allocation 模式）**：
1. 选择费用分摊方案
2. 按费用项逐项计算：
   - fixed：直接取 fixedAmount
   - invoice：取发票总额
   - manual：用户输入
3. 按分配方式分摊到各门店：
   - fixed：固定金额
   - ratio：按比例
   - quantity：按数量占比
   - manual：手动输入
4. 最后一项强制返回 0 消除浮点误差（groupRemaining）
5. 报销说明按费用类型分行组织

### 5.3 认证与权限流程

```
登录 → JWT token（7天有效期）→ localStorage 存储
  ↓
每次 API 请求 → Authorization: Bearer xxx
  ↓
server/middleware/auth.ts → 验证 JWT → event.context.user 挂载
  ↓
requireRole(event, ...roles) → 从 context.user 读取角色 → 权限校验
  ↓
前端路由守卫 auth.global.ts → 未登录跳转 /login
```

## 六、技术规范要点

### 前端开发宪法（8 条强制规范）

1. 颜色零硬编码：使用 tokens.css 中的 CSS 变量
2. 字号零硬编码：使用 --font-size-* 变量
3. 间距零硬编码：使用 --spacing-* 变量
4. Composable 模式：数据逻辑通过 composable 复用
5. 类型定义：所有接口数据有 TypeScript 类型
6. 组件复用：CRUD 使用 CrudTable + EditDialog
7. 页面结构：PageHeader + 内容区
8. ECharts 配色：JS 中无法用 CSS 变量，值与 tokens.css 保持一致并注释

### 后端 API 规范

- 文件路由：Nuxt 约定（index.get.ts / index.post.ts / [id].put.ts 等）
- 权限校验：requireRole(event, ...roles) 兜底 + middleware 统一认证
- 操作日志：每个 CUD 操作记录日志
- 错误处理：服务端关键逻辑错误必须显式日志输出
- Decimal 序列化：Prisma Decimal 类型需转 Number 再返回

### 文件存储

- 发票 PDF：`data/uploads/invoices/{batchNo}/`
- 明细表 XLS：`data/uploads/details/`
- 合同 PDF：`data/uploads/contracts/`
- DB 只存相对路径，通过 `/files/[...path]` 路由访问
- 删除记录时同步删除物理文件
