## 一、项目概述

泰兴超市信息部综合管理平台，用于通讯费发票报销、计提费用核算、合同管理等工作。
架构：EXE配置器(Go+Wails) + Web应用(Nuxt 4)分离架构。

## 二、技术栈

| 层 | 技术 | 说明 |
|---|------|------|
| 前端 | Nuxt 4 + Vue 3 + Element Plus | 橙色主题(#E6A23C)，浅色统一风格 |
| 图表 | ECharts | 浅色主题 |
| 状态 | Pinia | |
| 工具 | @vueuse/core, dayjs | |
| ORM | Prisma 7 | driver adapter(@prisma/adapter-mariadb) + prisma.config.ts |
| 数据库 | MySQL 8.0（远程） | 不在本机安装，EXE 远程配置连接 |
| EXE | Go + Wails | 配置器+服务启停+日志+数据库初始化/升级 |
| 密码加密 | Windows DPAPI | 数据库密码加密保存在本机，不写入明文文件 |
| 打印 | CSS @media print + pdfjs-dist | A5打印，无插件 |

## 五、关键业务规则（速查）

1. **计提模板**：每个运营商+门店一套，承担部门默认等于门店(特殊行可修改)，电信模板"名称"列填号码匹配明细表，联通/移动填费用类型
2. **电信倒推计算**：非号码行费用 = 发票总额 - 其他号码行费用之和
3. **报销说明**：4种预设格式统一以{年月}{运营商}{部门}开头，模板编辑页支持实时预览
4. **数据源统一**：门店/部门/机构数据通过composable(useStoreData)共享，门店管理与计提模板共用同一份数据
5. **A5打印（计提表）**：一个批次所有门店行合并到同一个A5表格，多门店时显示小计+合计，行数少时整体居中，行数多(>8行)自动紧凑模式，批量打印每2个A5排一张A4
6. **发票打印**：PDF.js渲染图片+HTML打印窗口，单张/批量均支持图片预览，2张A5排1张A4
7. **发票命名**：`{运营商}_{年月}_{序号}_{承担部门}_{金额}.pdf`，承担部门为多部门时用顿号连接
8. **批次号格式**：`{年月}{运营商缩写}{2位序号}`，如 `202606DX01`。缩写：电信DX/联通LT/移动YD/广电GD
9. **发票多部门**：一张发票可关联多个部门（如总部信息部+团购部），上传时OCR确认阶段门店多选，列表用多个Tag展示
10. **计提生成**：电信按明细表（号码行匹配明细表取应收合计，非号码行倒推计算=发票总额-号码行之和）；移动/联通按发票（直接填发票价税合计）
11. **多门店均摊**：一张发票涉及多个门店时，发票金额按门店数均摊，确保各门店小计之和=批次总额
12. **报销说明**：4种预设格式统一以{年月}{运营商}{部门}开头，非号码行只在第一个承担部门下列出避免重复

## 六、开发规范

1. **静态原型先行**：先用假数据做前端原型，确认交互后再开发后端
2. **禁止原生开发**：必须使用Element Plus组件库
3. **Design Token**：颜色/间距/字体用CSS变量，禁止硬编码
4. **组件复用**：同一UI出现超过2次必须封装为通用组件
5. **模块边界**：页面/组件/接口按模块分目录
6. **Git阶段性提交**：每个功能模块完成后提交
7. **页面说明规范**：每个功能页面顶部加el-alert使用说明区块(4-6条要点)
8. **中文locale**：Element Plus全局配置中文locale，日期/表格等控件显示中文
9. **视觉统一**：页面卡片用全局.card类，不用el-card组件；CSS用design token变量

## 六点五、文件存储架构

### 存储策略
- 文件存 data/uploads/ 目录（已在 .gitignore 中）
- DB 只存相对路径 + 解析后结构化数据（JSON）
- 远程 MySQL 不存 BLOB，避免网络传输瓶颈

### 目录结构
```
data/uploads/
├── invoices/{batchNo}/    # 发票PDF按批次分组
├── details/               # 明细表XLS
└── contracts/             # 合同PDF
```

### 各模型文件字段
| 模型 | 字段 | 类型 | 说明 |
|------|------|------|------|
| Invoice | filePath | VarChar(500) | PDF路径（已有） |
| DetailTable | filePath | VarChar(500) | XLS路径（本次新增） |
| Contract | filePath | VarChar(500) | PDF路径（本次新增） |

### 安全要求
- 文件名用 path.basename() 过滤防路径穿越
- 删除DB记录时同步删除物理文件
- 上传大小限制：PDF 10MB / XLS 5MB

## 十、开源准备

项目计划后续开源到 GitHub（Apache-2.0）。详细检查清单见 `docs/开源准备清单.md`。

### 数据分层规范（从现在起执行）

| 层级 | 文件 | 说明 | 公开仓库 |
|------|------|------|----------|
| 演示数据 | `web/prisma/seed.demo.ts` | 虚构门店/供应商/服务器，所有密码为占位符 | ✅ 包含 |
| 内部数据 | `web/prisma/seed.ts` | 真实门店/供应商/服务器/支付配置 | ❌ .gitignore 排除 |
| 内部文档 | `docs/副本*.xlsx` | 真实预算 Excel | ❌ .gitignore 排除 |
| 配置 | `.env` / `config.json` | 数据库地址/密码 | ❌ .gitignore 排除 |
| 示例配置 | `.env.example` | 占位符，无真实值 | ✅ 包含 |

### 关键规则

1. **不在代码/seed/日志/配置/文档中硬编码真实内部数据**
2. **seed.ts（真实数据）已加入 .gitignore，公开仓库只含 seed.demo.ts**
3. **prisma.config.ts 通过 SEED_MODE 环境变量切换 demo/internal seed**
4. **当前内部 Git 历史包含真实业务数据，公开仓库必须创建全新 Git 历史**
5. **后端开发完成后，统一进行一次公开版清理（composables 数据替换+文档清理+许可证文件）**
6. **开源前建议更换 MySQL root 密码**

### 公开前再确认要求

创建公开 GitHub 仓库前，必须再次执行以下检查：

1. **确认 `seed.ts` 曾出现在旧 Git 提交中** → 已确认，从 `d468b29` 到 `ba54020` 期间被跟踪 → **不沿用旧历史，创建全新仓库**
2. **确认真实 Excel 曾出现在旧 Git 提交中** → 已确认，`docs/副本20260326泰兴总部门店通讯费用预算表2.xlsx` 曾被跟踪 → **不沿用旧历史**
3. **确认内部 IP 曾出现在旧 Git 提交中** → 已确认曾出现在旧仓库历史 → **不沿用旧历史**
4. **确认 composables 中的真实数据曾出现在旧 Git 提交中** → 已确认，useStoreData/useBudgetData/usePaymentData/useServerData 等含真实门店名/预算/商户号/服务器信息 → **不沿用旧历史**
5. **结论：公开仓库必须 `git init` 创建全新历史，不 `git remote` 到旧仓库**
6. **旧仓库标记为 `internal-only`，永不推送到 GitHub**
