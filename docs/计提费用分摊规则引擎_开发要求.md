# 计提模板改造为通用费用分摊规则引擎

## 概述

当前计提模板是"单门店维度"（每个运营商+门店一套），联通/移动的"按发票模式"只做简单均摊（发票金额/门店数），无法处理"一张发票跨多门店、不同费用类型有不同分摊规则"的真实业务场景。

本次改造新增**通用费用分摊方案**（FeeAllocationScheme），作为独立于运营商和门店的规则引擎，支持四种分摊方式，按费用类型分行展示，所有运营商可复用。保留现有两种计提模式不变，新增第三种 allocation 模式。

## 核心设计

### 费用分摊方案结构

```typescript
// 费用项 — 一项独立费用
interface FeeItem {
  feeType: string          // 费用类型：宽带 / 专线 / 固话 / 固定IP / 其他
  name: string             // 费用名称，如"商务宽带套餐"、"联通专线"
  amountSource: 'fixed' | 'invoice' | 'manual'  // 金额来源
  fixedAmount: number      // 固定金额（amountSource=fixed 时使用）
  allocationMode: 'fixed' | 'ratio' | 'quantity' | 'manual'  // 分摊方式
  allocations: FeeAllocation[]  // 分摊明细
  remark: string
}

// 分摊明细 — 一个费用项如何拆分到各门店
interface FeeAllocation {
  store: string            // 门店
  dept: string[]           // 承担部门
  value: number            // fixed=金额 / ratio=百分比 / quantity=数量
  remark: string
}

// 费用分摊方案 — 一组费用项的集合
interface FeeAllocationScheme {
  id: number
  name: string             // 方案名称，如"联通宽带套餐分摊"
  carrier: string          // 运营商（空=通用）
  items: FeeItem[]         // 费用项列表
  reimbursementFormat: string   // 报销说明格式
  reimbursementCustom: string   // 自定义报销说明
  status: number           // 1=启用 0=禁用
}
```

### 四种分摊方式计算逻辑

| 方式 | amountSource | 计算 | 示例 |
|------|-------------|------|------|
| 固定金额 | fixed | allocations[].value 即为各门店金额 | 专线300，总部300 |
| 比例 | fixed/invoice | 金额 × value / 100 | 宽带199，总部50%=99.5 |
| 按数量 | fixed/invoice | 金额 × value / sum(values) | 宽带4条，时代1条=199×1/4 |
| 手动 | manual | 生成时用户输入各门店金额 | 固话，每月不同 |

### 业务示例（联通6月费用分摊方案）

```
费用项1: 联通专线 | fixed | 300 | fixed | [{总部信息部, 300}]
费用项2: 商务宽带套餐 | fixed | 796 | fixed | [{门店A,199},{门店B,99.5},{门店C,99.5},{门店D,99.5},{门店E,99.5},{总部信息部,199}]
费用项3: 固定IP | fixed | 50 | fixed | [{总部信息部, 50}]
费用项4: 固话 | manual | 0 | manual | [{时代店,0},{总部信息部,0}]  // 生成时手动输入
```

## 数据模型变更

### 新增模型：FeeAllocationScheme

文件：`web/prisma/schema.prisma`

```prisma
/// 费用分摊方案表 — 通用费用分摊规则引擎，支持跨门店分摊
model FeeAllocationScheme {
  id                   Int      @id @default(autoincrement())
  /// 方案名称，如"联通宽带套餐分摊"
  name                 String   @db.VarChar(100)
  /// 运营商（空字符串=通用，不绑定特定运营商）
  carrier              String   @db.VarChar(20) @default("")
  /// 费用项列表，JSON 存储 FeeItem[]
  items                Json     @default("[]")
  /// 报销说明格式
  reimbursementFormat  String   @db.VarChar(50) @default("分摊明细型")
  /// 自定义报销说明
  reimbursementCustom  String   @db.VarChar(2000) @default("")
  /// 状态：1=启用，0=禁用
  status               Int      @default(1)
  /// 更新时间
  updateTime           DateTime @default(now()) @db.DateTime(0)

  @@index([carrier])
  @@index([status])
  @@map("fee_allocation_schemes")
}
```

### Accrual 模型扩展

`web/prisma/schema.prisma` 中 Accrual.method 字段值域扩展为：`detail`（按明细表）/ `invoice`（按发票均摊）/ `allocation`（按费用分摊方案）。无需改 schema（VarChar(20) 够用），仅改代码逻辑。

### AccrualRow 类型扩展

`web/app/types/accrual.ts` 中 AccrualRow 增加 feeType 字段：

```typescript
export interface AccrualRow {

  feeType: string  // 新增：费用类型（宽带/专线/固话/固定IP/其他）
}
```

### 改造：计提生成 API

文件：`web/server/api/accruals/generate.post.ts`

请求体新增参数：
```typescript
{
  batchId: number
  templateOverrides?: Record<string, number>  // detail/invoice 模式用
  detailTableId?: number                       // detail 模式用
  schemeId?: number                            // 新增：allocation 模式用
  manualAdjustments?: Record<string, number>   // 新增：手动费用项的各门店金额
}
```

计提方式判断逻辑改为三选一：
- `schemeId > 0` → allocation 模式
- `detailTableId > 0` 或运营商=电信 → detail 模式
- 其他 → invoice 模式

### allocation 模式生成算法（新增）

```
1. 加载费用分摊方案（FeeAllocationScheme）
2. 遍历方案 items 中每个 FeeItem：
   a. 确定金额：
      - fixed → fixedAmount
      - invoice → 批次发票总额
      - manual → 从 manualAdjustments 取用户输入值
   b. 按分摊方式计算各门店金额：
      - fixed → allocations[].value 即金额
      - ratio → 金额 × value / 100
      - quantity → 金额 × value / sum(values)
      - manual → manualAdjustments[store] 
3. 按门店汇总所有费用项金额
4. 生成 AccrualRow[]（每费用项×每门店一行，带 feeType）
5. 校验：sum(各门店小计) vs 发票总额，差异>0.01 时在返回结果中标记 warning
6. 生成报销说明（按费用类型组织）
7. 存库（groups JSON 含完整快照，方案修改不影响历史）
```

### 新增：计提表编辑 API

文件：`web/server/api/accruals/[id].put.ts`（扩展现有 PUT）

现有 PUT 仅更新 status。扩展为支持编辑 groups 内容（手动调整变动费用项金额）：
- 接收 `{ groups?: AccrualGroup[], status?: string }`
- groups 更新时重新计算 subtotal/totalAmount/报销说明
- 操作日志记录"编辑计提表"

## 注意事项

1. **不破坏现有逻辑**：detail 模式（电信号码匹配）和 invoice 模式（简单均摊）保留不变，allocation 作为第三种模式新增
2. **历史快照**：计提记录 groups JSON 存储完整分摊结果，方案修改不影响已生成的计提表
3. **通用性**：FeeAllocationScheme 不绑定特定运营商，carrier 为空时为通用方案，电信/移动/联通/未来业务都可复用
4. **前端规范**：新增页面和组件严格遵守前端开发宪法（PageHeader + el-alert + CrudTable + Design Token + composable 单例 + 类型独立文件）
5. **报销说明生成函数有两份**（`useAccrualData.ts` 前端预览用 + `generate.post.ts` 后端生成用），改动需同步两处
6. **数据库迁移**：新增表，不修改现有表结构，EXE 升级数据库时自动生效
