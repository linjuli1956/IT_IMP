# 管理员账号与密码

本项目公开仓库不包含真实账号、密码、业务数据或数据库快照。为了让全新的空数据库可以使用，系统只在首次初始化时创建一个管理员；它不是业务 Seed。

## 默认值与首次登录

公开示例的默认账号是 `admin`，默认密码是 `123456`。部署者可以在首次初始化前改掉它：

- EXE：在“数据库配置”页的“首次管理员”区域填写账号和密码，再点击“初始化数据库”。该密码只用于本次初始化，不保存到 EXE 的 `config.json`。
- Docker：在 `deploy/docker/.env` 中设置 `INITIAL_ADMIN_USERNAME` 与 `INITIAL_ADMIN_PASSWORD`，默认是 `admin / 123456`。MySQL 密码与 JWT 密钥也只在同一个 `.env` 中配置，该文件已被 Git 忽略。完整命令见 [Docker 部署文档](../deploy/docker/README.md)。

首次登录后，从右上角用户菜单选择“修改密码”。管理员密码以 bcrypt 哈希保存于 `users.passwordHash`，数据库中不保存明文。

## 一次性创建规则

初始化脚本会先检查 `users` 表：

- 表中没有用户：创建首个管理员；
- 表中已有任意用户：跳过创建，不改变任何账号或密码；
- EXE 的“初始化数据库”会主动删除并重建目标数据库，因此会重新创建首次管理员；Docker 的常规重启不会重建数据库。

这项规则避免了升级镜像、修改环境变量或容器重启覆盖已使用的密码。

对于已使用旧版 EXE 完成建表、但尚未创建任何用户的环境，不要再次点击“初始化数据库”。请更新 EXE 后在“数据库配置”页填写首次管理员信息，点击“补建首次管理员”；该操作不会删除数据库，也不会执行迁移。

## 忘记密码与数据库故障

正常情况下，应由已登录管理员在“用户管理”中重置普通用户密码，或由用户自行修改密码。若唯一管理员无法登录，Docker 可先在 `deploy/docker/.env` 中填写新的 `INITIAL_ADMIN_PASSWORD`，再使用显式 `--reset` 运维命令；EXE 则在配置器的“初始密码”中填入新的临时密码，然后点击“重置管理员密码”。两种方式都不会重建数据库或影响其他用户。

登录密码的唯一事实来源是数据库的哈希值。因此，Docker Secret、环境变量和 EXE 配置器无法绕过“数据库不可连接”的问题：它们只能在连接到 MySQL 后创建或更新哈希。数据库数据卷丢失时，应将其视为新部署，重新初始化并创建新的管理员。

不要将真实密码写入 README、Issue、截图或 Git 提交。`.env` 仅保存在部署服务器且已被 Git 忽略；疑似泄露时立即更换密码，详见 [安全策略](../SECURITY.md)。
