# 开发习惯与项目模板规范

> 适用范围：所有 Windows 内网部署的 Web 管理系统项目  
> 版本：V2.0 | 日期：2026-07-24  
> 用途：新项目启动时参照此模板确定架构和技术栈；与 AI 沟通时快速同步开发偏好  
> V2.0 更新：基于泰兴超市信息部综合管理平台项目实践，沉淀开发宪法、Composable 模式、组件清单等

---

## 一、架构模式

采用 **EXE配置器 + Web应用** 分离架构：

**EXE配置器职责：**
- 数据库配置（主机/端口/用户名/密码/数据库名）
- 测试连接
- 初始化数据库（一键自动建表 + 默认数据）
- Web端口配置
- 启动/停止 Web 服务
- 实时日志输出展示
- 配置持久化（config.json，与EXE同目录）

**Web应用职责：**
- 业务功能（页面交互、数据管理）
- 首页数据大屏
- 用户认证

## 三、开发宪法（强制规范）

> **此章节为全项目最高优先级规范，所有开发者（含 AI Agent）必须严格遵守。**

### 第1条 颜色零硬编码
- **禁止**在 `.vue` / `.css` / `.scss` / `.ts` 任何位置出现硬编码十六进制颜色值
- **必须**使用 `tokens.css` 中的 CSS 变量，如 `var(--color-primary)`
- **唯一例外**：ExcelJS / ECharts / Canvas / el-tag color 等 JS 库配置无法使用 CSS 变量时，允许 hex 值，但**必须加注释标注对应的变量名**

### 第2条 字号零硬编码
- **禁止** CSS 中硬编码 `font-size` 值
- **必须**使用字号变量：`--font-size-title`(18px) / `--font-size-subtitle`(16px) / `--font-size-body`(14px) / `--font-size-small`(13px) / `--font-size-mini`(12px) / `--font-size-micro`(11px) / `--font-size-display`(28px) / `--font-size-large`(22px) / `--font-size-icon`(20px)
- 图标尺寸（如 el-icon font-size）允许硬编码但**必须加注释**标注"图标尺寸，非文本字号"

### 第3条 间距/圆角/阴影零硬编码
- `border-radius` 必须使用 `--radius-*`（card 8px / btn 4px / input 4px / dialog 8px / small 3px）
- `box-shadow` 必须使用 `--shadow-*`
- `margin/padding/gap` 优先使用 `--spacing-*`

### 第4条 新增 Design Token 流程
1. 在 `tokens.css` 的 `:root` 中新增变量定义
2. 在页面中引用 `var(--新变量名)`
3. 同步更新前端规划文档的 Token 清单

### 第5条 Composable 数据源模式
- 每个业务模块封装为 `composables/use{Module}Data.ts`
- 文件结构必须包含：类型 re-export → 常量导出 → 预设数据 → 单例 ref → CRUD 函数 → useXxxData 导出
- **禁止**页面内直接定义 ref 数据源

### 第6条 类型定义模式
- 类型独立文件 `types/{module}.ts`
- `types/index.ts` 统一 re-export
- Composable 中 `import type` from `~/types/xxx` 并 re-export

### 第7条 组件复用强制
- 同类 UI 超过 2 次必须封装
- 通用组件放 `components/common/`
- 组件内同样遵守第 1~3 条

### 第8条 页面结构强制
- 每个功能页面必须包含：PageHeader + el-alert 使用说明 + 主内容区（CrudTable）+ 新增/编辑弹窗

### 违规自检清单
```bash
# 检查硬编码颜色（排除注释行）
grep -rn '#[0-9A-Fa-f]\{6\}' --include='*.vue' --include='*.ts' --include='*.css' web/app/
# 检查硬编码字号
grep -rn 'font-size:.*px' --include='*.vue' web/app/
# 检查硬编码圆角
grep -rn 'border-radius:.*px' --include='*.vue' web/app/
```

## 四、EXE配置器规范

### 4.1 界面布局

三个标签页：
1. **数据库配置**：表单 + 保存配置 + 测试连接 + 初始化数据库
2. **服务管理**：端口配置 + 启动/停止按钮 + 服务状态显示
3. **运行日志**：实时日志输出 + 清空日志

### 4.2 配置文件

`config.json` 与 EXE 同目录：
```json
{
  "database": {
    "host": "127.0.0.1",
    "port": 3306,
    "username": "root",
    "password": "",
    "dbname": "my_platform"
  },
  "webPort": 3000
}
```

### 4.3 初始化数据库

点击"初始化数据库"按钮：
1. 自动创建所有数据表（CREATE TABLE IF NOT EXISTS）
2. 插入默认数据（管理员、基础配置等）
3. 使用 INSERT IGNORE 避免重复

### 4.4 服务管理

- 启动：查找Web服务入口，通过环境变量传递数据库配置
- 停止：Kill 进程
- 日志：异步读取 stdout/stderr，通过事件推送到前端

## 五、Web应用规范

### 5.1 前端风格

- **浅色主题**：白色/浅灰背景，深色文字
- **全站统一**：所有页面字体、控件、间距一致
- **控件复用**：统一组件，禁止不同界面不同风格
- **禁止原生开发**：所有 UI 用 Element Plus 组件库
- **拖拽上传**：文件上传支持拖拽

### 5.2 Design Token 完整清单

所有颜色、字号、间距用 CSS 变量统一定义，禁止页面内硬编码。

**颜色变量分类：**
- 主色系（橙色）：`--color-primary` / hover / active / light / border
- 功能色：`--color-success` / `--color-warning` / `--color-danger` / `--color-info`
- 功能色浅背景：`--color-success-light` / `--color-warning-light` / `--color-danger-light` / `--color-info-light`
- 文字色：`--text-primary` / `--text-regular` / `--text-secondary` / `--text-placeholder`
- 边框/背景：`--border-base` / `--border-light` / `--border-lighter` / `--bg-page` / `--bg-card` / `--bg-hover`
- 业务配色：门店行底色（11色循环）/ 支付服务商底色 / 业务类型配色

**字号变量：** title(18) / subtitle(16) / body(14) / small(13) / mini(12) / micro(11) / display(28) / large(22) / icon(20)

**圆角变量：** card(8px) / btn(4px) / input(4px) / dialog(8px) / small(3px)

**间距变量：** page(20) / card(16) / form-item(18) / btn-gap(12) / table-row(48)

### 5.3 Composable 数据源模式（核心架构）

每个业务模块的数据源封装为 `composables/use{Module}Data.ts`，采用单例模式：

```typescript
// composables/useXxxData.ts
import type { XxxItem } from '~/types/xxx'
export type { XxxItem }

// 1. 常量导出（选项数组、映射表）
export const xxxOptions = [...]

// 2. 预设数据（静态原型阶段使用）
const presetXxx: XxxItem[] = [...]

// 3. 单例状态（模块级 ref，非函数内）
const xxxList = ref<XxxItem[]>([...presetXxx])

// 4. CRUD 函数（模块级）
function addXxx(data: Omit<XxxItem, 'id'>) { ... }
function updateXxx(id: number, data: Partial<XxxItem>) { ... }
function deleteXxx(id: number) { ... }

// 5. 导出
export function useXxxData() {
  return { xxxList, xxxOptions, addXxx, updateXxx, deleteXxx }
}
```

**命名规范：** 各模块的 `statusOptions` 必须加模块前缀（如 `domainStatusOptions`、`paymentStatusOptions`），避免多模块同时使用时命名冲突。

### 5.4 页面结构模式

每个功能页面必须遵循以下结构：

```vue
<template>
  <div class="page-container">
    <!-- 1. 页面标题 + 操作按钮 -->
    <PageHeader title="xxx管理">
      <template #actions>
        <el-button type="primary" @click="handleAdd">新增</el-button>
      </template>
    </PageHeader>

    <!-- 2. 使用说明 -->
    <el-alert type="info" :closable="false" show-icon class="usage-alert">
      <template #title>使用说明</template>
      <div class="usage-tips">
        <p>1. ...</p>
      </div>
    </el-alert>

    <!-- 3. 概览卡片（可选） -->
    <el-row :gutter="16" class="stat-row">...</el-row>

    <!-- 4. 搜索栏 -->
    <div class="card filter-bar">...</div>

    <!-- 5. 主表格 -->
    <div class="card">
      <CrudTable :columns="columns" :data="filteredData" @edit="..." @delete="...">
        <template #slotName="{ row }">...</template>
      </CrudTable>
    </div>

    <!-- 6. 新增/编辑弹窗 -->
    <el-dialog v-model="dialogVisible" :title="dialogTitle" width="780px">
      <el-form :model="formData" :rules="rules">...</el-form>
    </el-dialog>
  </div>
</template>
```

### 5.5 组件清单

| 组件名 | 说明 | 使用页面数 |
|--------|------|-----------|
| `PageHeader` | 页面标题 + 操作按钮插槽 | 12+ |
| `CrudTable` | 增删改查表格（复选框/批量删除/列头筛选/批量复制/省略提示） | 6+ |
| `EditDialog` | 通用编辑弹窗 | 3+ |
| `DragUpload` | 拖拽上传（支持自定义文件类型） | 3+ |
| `StatCard` | 指标卡片（左侧4px主色竖条 + 图标 + 数值 + 标签） | 3+ |
| `ChartCard` | ECharts 图表卡片（SSR兼容 + 按需导入） | 4 |
| `SensitiveValue` | 敏感信息脱敏显示（密码/账号），眼睛图标切换 | 3+ |
| `ReimbursementText` | 报销说明 + 复制按钮 | 2+ |

### 5.6 首页数据大屏

- 核心指标卡片（StatCard，业务+IT两组）
- 趋势图（折线）、占比图（饼图）、分布图（柱状）、排名图（条形）
- 从 composable 真实数据派生，不使用独立假数据
- 浅色主题 ECharts，配色与 tokens.css 一致

## 六、开发流程

```
阶段1: EXE配置工具（Go+Wails）
  ├─ Wails项目初始化
  ├─ 数据库配置 + 测试连接
  ├─ 初始化数据库（建表SQL）
  ├─ 端口配置 + 启停服务 + 日志
  ├─ 编译打包EXE（验证≤15MB）
  └─ 目标：一键配置部署工具可用

阶段2: 前端原型（静态假数据）  ← 当前阶段已完成
  ├─ Nuxt + Element Plus（浅色统一风格）
  ├─ Design Token + 开发宪法
  ├─ 布局组件 + 通用组件
  ├─ 全部页面原型 + Composable 数据源
  └─ 目标：看到完整界面，确认交互

阶段3: 数据库设计 + 建表
  ├─ Prisma schema 定义数据模型
  ├─ MySQL 数据库初始化 SQL
  └─ 预设数据种子脚本

阶段4: 后端 API
  ├─ Nuxt server routes 实现 CRUD
  ├─ JWT 认证中间件
  ├─ 文件上传（PDF/XLS）
  └─ composable 从假数据切换为 API 调用

阶段5: 高级功能（OCR等）
  └─ RapidOCR + PDF + ZIP + 确认

阶段6: 前后端联调 + 登录认证

阶段7: 测试与部署
```

## 九、模块边界规则

| 规则 | 说明 |
|------|------|
| 页面按模块分目录 | `pages/invoices/`, `pages/accruals/`, `pages/it/` |
| 组件按模块分类 | `components/common/`, `components/invoice/` |
| 数据源按模块封装 | `composables/use{Module}Data.ts`（单例模式） |
| 类型定义按模块分文件 | `types/{module}.ts` + `types/index.ts` 统一导出 |
| 常量随数据源导出 | 选项数组、映射表等在 composable 中 `export const` |
| 禁止跨模块直接引用 | 需要时提取到 common 或通过参数传递 |
| 同类UI超过两次封装 | 避免重复代码 |
| 命名加模块前缀 | 如 `domainStatusOptions` 而非通用 `statusOptions` |
