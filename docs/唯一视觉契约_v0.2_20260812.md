## 二、按钮平铺/更多判定规则

### 2.1 判定表

| 维度 | 平铺（直接显示为按钮/文字操作） | 收纳进"更多"下拉 |
|------|------|------|
| **频率** | 高频（每条记录都可能用） | 低频（偶发使用） |
| **危险性** | 安全操作（编辑、查看） | 危险操作（删除、清除） |
| **敏感性** | 非敏感（不含密码/凭据） | 敏感（凭据、密码相关） |
| **跳转** | 当前页内操作 | 外部跳转（进入管理、打开新页签） |
| **导航** | 当前页内操作 | 详情页导航（打开独立详情页） |
| **空间** | 行/Footer 空间足够（≤3 个平铺按钮） | 空间不足或超过 3 个操作 |

### 2.2 核心原则

- **"更多"不是默认答案。** 空间足够时不要多此一举。
- **单项通常不进入更多。** 但低频敏感操作可使用低强调独立入口（如文字按钮），不能为了规则而制造只有一个菜单项的"更多"按钮。
- **每页、每个 Drawer 先列操作优先级。** 不允许为了统一而机械塞进更多。
- **危险操作可平铺。** 删除按钮可以平铺为红色文字操作并保留二次确认，不必强制收纳。

## 三、复制与导出能力边界

> **本阶段只写契约，不编码。** 先在 network-devices 样板页验证，再推广。

### 3.1 复制能力

| 能力 | 描述 | 触发方式 | 适用字段 |
|------|------|---------|---------|
| 复制单个字段 | 在表格列/Drawer 信息项上提供复制按钮 | 字段旁 `CopyDocument` 图标按钮 | 白名单字段（见 3.3） |
| 复制记录摘要 | 复制当前记录的关键信息为纯文本 | 行操作或 Drawer 内"复制摘要"按钮 | 格式由各页面定义 |

**现有基础：**
- `ReimbursementText.vue` 已实现 `copyText()` 函数（`navigator.clipboard.writeText` + `execCommand` 降级）
- `CrudTable.vue` 已实现 `batch-copy` 事件（`showBatchCopy` prop + 批量操作栏）

**v0.2 规范：**
- 复制函数提取为 `composables/useClipboard.ts`，统一 `navigator.clipboard` + 降级逻辑
- 字段级复制：在 `AssetTable` 列配置中增加 `copyable: true` 选项，自动渲染图标
- 所有复制必须通过字段白名单，不能按整行对象序列化

**复制权限：**
- 复制不依赖 `canEdit`；查看者既然能看到非敏感字段，就应能复制
- 查看者可复制白名单字段（IP、域名、资产编号、序列号、设备名称等）

**不做什么：**
- `password`、`dbPassword`、`token` 等绝不复制
- 服务器 `account` / `dbAccount` 本阶段也不进入复制白名单，后续如需开放再单独确认
- 不按整行对象序列化复制

### 3.2 导出能力

| 能力 | 描述 | 触发方式 | 适用范围 |
|------|------|---------|---------|
| 导出当前页 CSV | 将当前页可见数据导出为 CSV 文件 | PageHeader 操作区"导出当前页 CSV"按钮 | 阶段 C 仅 network-devices 样板页 |

**v0.2 规范：**
- 按钮文案必须准确为 **"导出当前页 CSV"**，不得写成"导出全部"或"导出筛选结果"
- 按钮放在 PageHeader `#actions` 插槽，位于"新增"按钮左侧
- 仅导出当前页可见的非敏感白名单列
- CSV 使用 **UTF-8 BOM**，确保中文 Excel 打开正常
- 不新增导出 API，不做 Excel/XLSX
- 导出仅管理员/操作员可用

**不做什么：**
- 不导出密码、凭据、Token
- 不导出 `account` / `dbAccount`（本阶段不开放）
- 不导出设计参考页（design/*、dev/*）
- 不在阶段 B 编码
- 不假装导出了全部筛选结果

**"全量筛选结果导出"为独立功能：**
- 以后作为单独功能需求
- 需先定义后端接口、权限、数据量限制和审计日志
- 不在本契约范围内

### 3.3 字段白名单与红线

| 字段 | 复制 | 导出 | 说明 |
|------|------|------|------|
| `password` | ❌ 绝不 | ❌ 绝不 | 服务器登录密码 |
| `dbPassword` | ❌ 绝不 | ❌ 绝不 | 数据库密码 |
| `token` | ❌ 绝不 | ❌ 绝不 | 认证令牌 |
| `account` | ❌ 本阶段不开放 | ❌ 本阶段不开放 | 服务器登录账号（后续单独确认） |
| `dbAccount` | ❌ 本阶段不开放 | ❌ 本阶段不开放 | 数据库账号（后续单独确认） |
| `internalIp` | ✅ | ✅ | 内网 IP |
| `externalIp` | ✅ | ✅ | 外网 IP |
| `domain` | ✅ | ✅ | 域名 |
| `serialNo` | ✅ | ✅ | 设备序列号 |
| `name` | ✅ | ✅ | 资产/设备名称 |
| `assetNo` | ✅ | ✅ | 资产编号 |

## 四、Overlay 层级规则

### 4.1 技术约束

Element Plus 的 Drawer / Dialog / Dropdown / Popover / MessageBox 使用**运行时层级管理**（JavaScript 动态计算 z-index 递增）。不能用一套固定 CSS z-index 强行覆盖，否则会出现：

- Drawer 内打开的更多菜单跑到 Drawer 后面
- Dialog 内打开的 Dropdown 被 Dialog 遮罩拦截
- MessageBox 被其他 Overlay 覆盖

### 4.2 v0.2 规则

1. **自定义项目层可定义基础 Token**（`tokens.css` 中已有的 `--z-sidebar` / `--z-header` 等），用于项目自有固定层元素
2. **Element Plus Overlay 优先使用其运行时层级管理**，不强行覆盖
3. **禁止在 `global.css` 对所有 `el-overlay` / `dropdown` / `popover` 强行覆盖固定层级**
4. **当前 `.el-overlay.is-message-box` 的 `9999 !important` 过渡补丁先不动**，不替换为其他数字
5. **后续若处理凭据清除确认层级**，必须单独验证 `modalClass` / `customClass` 实际挂载位置，再做局部修复，不能影响全项目 30 余处 MessageBox
6. **禁止后续页面自行写新的 z-index 魔法数字**

### 4.3 验收矩阵

> 阶段 C 样板页及后续每次涉及 Overlay 的修改，必须验证以下嵌套场景：

| 场景 | 预期结果 | 验证方法 |
|------|---------|---------|
| Drawer → Dropdown | Dropdown 菜单在 Drawer 之上，可正常点击 | 在服务器 Drawer Footer 点击"更多" |
| Dialog → Dropdown | Dropdown 菜单在 Dialog 之上，可正常点击 | 在 ServerCredentialDialog 点击"更多" |
| Dialog → MessageBox | MessageBox 在 Dialog 之上，可正常点击 | 在 ServerCredentialDialog 点击"清除已保存凭据" |
| Tooltip | Tooltip 在所有 Overlay 之上 | 在任意表格行 hover 显示 Tooltip |
| Message | Message 在所有 Overlay 之上 | 在任意操作后观察 ElMessage 提示 |

## 六、产品决策记录

> 以下 4 条决策由用户在 2026-08-12 审计复核中明确指示。

### 决策 1：网络设备暂不增加密码字段

**决策：** 网络设备是设备台账与拓扑模块，不增加密码字段。

**理由：** 网络设备（交换机、路由器、防火墙、AP）的登录信息保存需求尚未明确。若未来确有需求，单独规划"设备凭据"能力，不能给所有资产表顺手加密码字段。

**适用范围：** `it/network-devices.vue`、`it/computers.vue`、`it/phones.vue`、`it/scales.vue` 均不增加密码字段。

### 决策 2：收紧"更多"菜单规则

**决策：** "更多"不是默认答案；单项通常不进入更多，但低频敏感操作可使用低强调独立入口。不能为了规则而制造只有一个菜单项的"更多"按钮。

- 高频且空间足够 → 平铺显示（例如编辑）
- 低频、敏感、危险、外部跳转、详情导航 → 收进"更多"（例如删除、服务器凭据、进入管理、打开详情）
- 每页、每个 Drawer 都先列出操作优先级，不允许为了统一而机械塞进更多
- 更多菜单不是默认答案，空间足够时不要多此一举

**执行：** 阶段 C 编码时按 2.3 审计结果修正 3 处单项进下拉问题（#3、#4、#5），落实 2.4 逐项决定。

### 决策 3：新增通用复制/导出能力（本阶段只写契约）

**决策：** 复制和导出是通用能力，但不能一次给所有菜单乱加。

- **复制：** 非敏感且用户已可见的字段复制，不依赖 `canEdit`；查看者可复制白名单字段；`password`/`dbPassword`/`token` 绝不复制；`account`/`dbAccount` 本阶段不开放；所有复制必须通过字段白名单
- **导出：** 阶段 C 样板只做"导出当前页 CSV"；不新增 API、不假装导出全部筛选结果；CSV 使用 UTF-8 BOM；仅导出当前页可见的非敏感白名单列；仅管理员/操作员可用
- **验证：** 先在 network-devices 样板页验证，再推广
- **全量筛选导出：** 以后作为单独功能需求，需先定义后端接口、权限、数据量限制和审计日志

**执行：** 阶段 B 只写契约（本文档第三章），阶段 C 在 network-devices 样板页编码验证。

### 决策 4：Overlay 层级规则

**决策：** 当前不能把 Element Plus 的 Dropdown / Popover / Drawer / Dialog 全部强制写成固定 z-index 数字。它们存在嵌套场景（Drawer 内打开更多菜单、Dialog 内打开更多菜单、Dialog 中再打开 MessageBox）。

- 自定义项目层可定义基础 Token
- Element Plus Overlay 优先使用其运行时层级管理
- 禁止在 `global.css` 对所有 `el-overlay` / `dropdown` / `popover` 强行覆盖固定层级
- 当前 `.el-overlay.is-message-box` 的 `9999 !important` 过渡补丁先不动
- 后续若处理凭据清除确认层级，必须单独验证 `modalClass` / `customClass` 实际挂载位置，再做局部修复
- 新增验收矩阵：Drawer→Dropdown、Dialog→Dropdown、Dialog→MessageBox、Tooltip/Message，均需可见且可点击

**执行：** 阶段 B 只写契约（本文档第四章），阶段 C 及后续每次涉及 Overlay 的修改必须验证验收矩阵。

## 七、v0.1 → v0.2 变更对照
